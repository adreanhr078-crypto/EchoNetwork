# عقد الدخول والحفظ والتصدير — تدقيق CP32

الحالة: **DESIGN_PARTIAL / INTEGRATION_OPEN**. هذه نتيجة فحص المصدر، وليست إثبات دخول حي أو قبول Android. المرجع التنفيذي: CHAPTER_QUALITY_EXECUTION_PLAN_2026-10-16.ar.md، البوابة1 ثم7. لا تتغير سلطة الخدمات أو مفاتيح الحفظ من هذه الوثيقة.

## الفجوة المثبتة

- `godot/scripts/boot.gd`: Windows/native يبدأ `native_journey.tscn` مباشرة؛ Web يبدأ `opening_web_room.tscn`. المدخل المحلي الحالي يتجاوز لغز الغلاف وكسر الشاشة.
- `src/features/gameplay/components/GodotOpeningRoom.tsx`: الغلاف المؤكد خادميًا يسبق iframe افتتاح Godot. التحقق من origin/source/nonce وإيصال الافتتاح موجود؛ هذا ليس ربطًا تلقائيًا بالحملة المحلية الكاملة.
- `src/domain/opening/openingHandoff.ts`: يحدد الاستئناف حسب الحالة الخادمية، ويتحقق من هوية الإيصال. لا يحوّل ملف حفظ محلي إلى إثبات خادمي.
- `native_journey_checkpoint.gd` لديه schema v2 وترحيل v1؛ `native_campaign_checkpoint.gd` لديه schema v1 وترتيب صارم للقرارات وكتابة tmp/bak. إصلاحات المختبر تحافظ على مفاتيحه القديمة وتشتق المرور من القرارات الصريحة.
- المثبت محليًا Godot4.8-dev7، وقوالبه الموجودة Windows debug/release فقط. Web/Android غير مثبتين في هذا الفحص. أغلفة Capacitor/Tauri القديمة ليست دليلًا على تصدير حملة Godot الحالية.

## قرار التنفيذ الذي يجب أن يثبته النموذج الأول

النسخة المستهدفة تستخدم حملة Godot native على Windows وAndroid، والخدمات الحالية تبقى مصدر صحة الحساب والإيصالات والمكافآت. لا نغلف حملة الويب الثقيلة تلقائيًا داخل الهاتف، ولا ننقل سلطة المكافآت إلى Godot. واجهة الغلاف الأصلية وعقدها الحالي يبقيان مرجع المحتوى والسلوك، ويجب ربطهما بمدخل النسخة الفعلي قبل قبول البوابة7.

تفاصيل جسر المصادقة وتبادل الإيصال **لم تعتمد ولم تنفذ بعد**؛ يلزم اختيار آلية متوافقة مع خدمة الحساب الفعلية وفحصها مع Argon. النموذج الأول يثبت مستخدمًا واحدًا وغلافًا واحدًا وإيصالًا حقيقيًا وانتقالًا واحدًا إلى الاستيقاظ، على Windows ثم Android، قبل تعميم الربط. لا تمرر session/access tokens في URL أو ملف حفظ أو سجل. لا تكفي قيمة `coverVerified=true` يكتبها العميل لإثبات الغلاف على الخادم.

## شروط التشغيل والقبول

| الحالة | السلوك المطلوب | دليل القبول المطلوب |
|---|---|---|
| حفظ جديد | لغز الغلاف ثم إيصال مؤكد ثم كسر الشاشة والاستيقاظ | تشغيل من مدخل الإصدار، بلا fixture أو كتابة تقدم تطويرية |
| إعادة المحاولة/إرسال مكرر | استرجاع الإيصال نفسه وعدم تكرار المكافأة | اختبار خدمة حقيقي ومعرّف استدعاء قابل للتتبع دون أسرار |
| إغلاق خلال الفيلم | يحفظ آخر حدث مكتمل فقط؛ لا قبول عقد أو رغبة بالتخطي | إغلاق/تشغيل فعلي عند نقاط محددة |
| استئناف قبل العقد أو الرغبة | إعادة السؤال الصريح، دون منح قرار أو قوى ضمنية | نافذة فعلية ومتابعة بإدخال اللاعب |
| شبكة مقطوعة | حالة قابلة للاستعادة ونص مفهوم، دون إيصال محلي مزيف | فصل الشبكة أثناء التحقق/الاستجابة ثم الاستئناف |
| حفظ قديم/غير صالح | ترحيل معروف أو رجوع آمن؛ لا فتح بوابة من enum أو collider قديم | عينات schema v1/v2 وعينة غير صالحة |
| Windows/Android | نفس ترتيب القصة والقرارات؛ أفقي؛ واجهة وإعدادات مناسبة لاحقًا | حزمة مستقلة ثم اختبار فعلي على الجهاز |

## ما يبقى OPEN

اختيار جسر الحساب وإثباته، نسخة المحرك وقوالب Android/Web المؤهلة، مسار01→10 الواحد بما فيه03→04 و07→08، ثم رحلة الغلاف→المستشفى من حفظ جديد، حزمة Windows حديثة وAndroid APK/AAB، وتقييم الأجهزة وGoogle Play. لا تغلق هذه القائمة بنجاح fixture يبدأ من04 أو08 أو09.
