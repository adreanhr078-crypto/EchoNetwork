# خطة بناء الإصدار المتبقي — 11.11 / Echo Network

التاريخ: **23 أكتوبر 2026** · المرجع: CP36 (`CP-20261017-01`) + تدقيق جاهزية آلي في هذه الجلسة.
الحالة: **PLAN — لا يغلق أي بوابة ولا يمنح PASS لأي مرحلة**. الوثيقة تحلّل آخر خطة في المستودع
(`CHAPTER_QUALITY_EXECUTION_PLAN_2026-10-16.ar.md`) وتحدد ما بقي فعلًا حتى تصل اللعبة إلى يد اللاعب،
مرتبًا حسب التبعية لا حسب الرغبة.

الأدلة الرقمية في هذه الوثيقة أُخذت من الشجرة الحالية عبر
`tools/release-readiness/audit_release_readiness.py`، والنتيجة الخام في
`audits/release-readiness-20261023/baseline.json`.

## 1. الخلاصة التنفيذية

1. **اللعبة ليست فكرة ولا نموذجًا أوليًا**: يوجد فصل متصل من 10 غرف (01→10) على مسار واحد، لاعب حقيقي
   `Echo V31` (68 مفصلًا، 19.8MB)، رحلة محفوظة بمخطط حفظ v1/v2، 76 مشهد Godot، 195 سكربتًا،
   151 فحص Godot، وتطبيق ويب React بمنفصل (110 ملف فحص + 3 e2e).
2. **ليست جاهزة للتنزيل**: لا توجد حزمة release حديثة، ولا قوالب تصدير، ولا مسار Android صالح للنشر،
   والمدخل المحلي يتجاوز لغز الغلاف، وتغطية الحركة والصوت والوجه ناقصة.
3. **آخر خطة سليمة الهيكل لكنها لم تُنفّذ إلا جزئيًا**: خطة 16 أكتوبر (14 بوابة) أُنجز منها ما يخص
   08/09/المختبر والكاميرا (CP32–CP33) وبعض الأداء (CP32)، وبقيت البوابات **8–14** كاملة،
   والبوابة **1** (عقد الدخول/الإيصال/الحزمة) لم تُحسم — وهي المانع الأول للنزول.
4. **الفرق الجوهري بين "لعبة ممتعة" و"لعبة تُنزّل"** ليس في الغرف بل في أربعة أشياء: المصدر الواحد للدخول
   والإيصال، تغطية الحركة (المشي/النهوض/القتال/التفاعل)، الصوت والإتاحة، ثم الحزمة والتوقيع والمتجر.
5. **التوصية**: فصل مسارين متوازيين — *مسار الإصدار (R)* و*مسار الفن والحركة (C)* — وإصدار
   **RC0 «البرولوغ»** (غلاف → استيقاظ → 03) على Windows ثم Android **قبل** إغلاق جودة الغرف 09–10،
   لأن RC0 هو ما يفكّ حجب الأداء والمنصات والعقد، ويحوّل المشروع من "غرف قيد الصقل" إلى "لعبة تُنزّل وتتقدّم".

## 2. فهم المستودع — ما هو اللعبة فعلًا

المستودع يحتوي **منتجين** يجب عدم خلطهما:

| الطبقة | المسار | الحالة | علاقتها بالإصدار |
|---|---|---|---|
| **لعبة Godot (المصدر المعتمد)** | `artifacts/eleven-eleven/godot/` | لاعب حقيقي، 10 غرف، حفظ، VFX، SFX | هذه هي **اللعبة التي تُنزّل** على Windows/Android |
| تطبيق ويب React + خدمات | `src/`, `functions/`, `workers/`, `data/` | غلاف/لغز الغلاف + سلطة الحساب والمكافآت + Canon | يبقى **مصدر الصحة** للإيصال والمكافأة، ولا يُغلَّف كحملة الهاتف |
| أغلفة منصات قديمة | `android/` (Capacitor), `src-tauri/`, `ios/` | أغلفة تطبيق الويب، ليست حملة Godot | تُهمَل في مسار الإصدار الحالي أو تُعاد توجيهها |
| أرشيف تجارب | `FlaxMigration/`, `art/godot/`, `audits/` | تاريخي | لا يدخل الحزمة |

نقاط الدخول الحقيقية (تحقّقت مباشرة):

- `godot/scenes/boot.tscn` → `scripts/boot.gd` يوجّه إلى `native_journey.tscn` (Windows) أو
  `opening_web_room.tscn` (Web).
- `native_journey_controller.gd`: الافتتاح → الصيانة → الأمن، ثم `native_campaign_controller.gd`
  (513 سطرًا): العينات → الأرشيف → المفاعل → التعقيم → المرآة → المختبر → المستشفى.
- الحفظ: `native_journey_checkpoint.gd` (schema v2 + ترحيل v1) و`native_campaign_checkpoint.gd`
  (schema v1، كتابة tmp/bak، ترتيب قرارات صارم).
- اللاعب: `scenes/player/echo_player.tscn` → `characters/echo_v31_adopted.tscn` → `echo_v31_adopted_high.glb`.
- الحركة: `assets/animations/v31/{idle,run,jump}_cp17.res` + `echo_v31_motion_adapter.gd` (Walk = Run مبطأ مؤقتًا).

**الخلاصة:** الهيكل ناضج؛ النقص في المصدر البشري للحركة والوجه، وفي الحزمة، وفي الأدلة القابلة للتحقق.

3. **الخطة تفترض أن أدلة CP هي مرجع كافٍ**. الواقع أن `audits/evidence/**` **كله** على Git LFS،
   و255/255 ملف تحقق في الشجرة الحالية غير موجود محليًا — أي أن الأدلة لا تُقرأ في نسخة نظيفة.

5. **لا بند لإزالة الملفات المعلّقة على LFS داخل runtime** (8 أصول مستخدمة فعليًا وناقصة محليًا)
   — فشل استيراد صامت يظهر كغرف ناقصة.
6. **الصوت**: الخطة تذكر «SFX_ONLY بلا موسيقى» وتذكر أصوات بيئة، لكن لا يوجد جرد صوتي ملزم

## 6. الخطة الشاملة — مسارَان متوازيان

المنطق: **R** يصنع لعبة تُنزّل وتُقاس؛ **C** يرفع جودتها. أي بند في C يمر عبر بوابة قبول واحدة،
وأي بند في R لا ينتظر إغلاق C بالكامل.

### مسار R — هندسة الإصدار

**R0 — إعادة قابلية البناء (أساس كل شيء)**
- تثبيت Godot **4.8-dev7** + قوالب التصدير المطابقة تمامًا (لا إصدار أعلى/أدنى).
- Blender: إما تنصيب كامل، أو `bpy` headless (متاح على PyPI؛ نسخة 4.5.x تعمل مع Python 3.11).
- `git lfs` في مسار البناء + استثناء `audits/**/*.json|md` الصغيرة من LFS (G-21).
- حل G-08: تنزيل 34 ملفًا أو إزالة مراجع الأصول غير المستخدمة؛ منع أي استيراد ناقص.
- استيراد نظيف بلا أخطاء سكربت، وحفظ `--headless --import` لوج كدليل.
- **مخرج**: `baseline.json` محدث + لوج استيراد + commit معروف.

**R1 — عقد الدخول والحفظ (فك G-02/G-03)**
- نموذج واحد: `boot.gd` → غلاف (لغز) → إيصال خادمي → كسر شاشة → تحميل → استيقاظ، على Windows.
- الجسر: HTTP من Godot إلى الخدمة الحالية، **بلا** تمرير access token في URL أو ملف حفظ.
- تثبيت مخطط الحفظ: حدث مكتمل واحد لكل خطوة، كتابة tmp/bak، ترحيل v1→v2، ورفض الحفظ التالف.
- اختبار الحالات السبع في عقد الدخول (جديد/مكرر/إغلاق/استئناف/شبكة/تالف/منصتان).
- **مخرج**: تشغيل من حفظ جديد بلا أي fixture، مع سجل إيصال واحد.

**R2 — حزمة Windows RC**
- preset إنتاجي (اسم، أيقونة، نسخة، بلا `tests/*`)، تصدير release، تشغيل من مجلد نظيف.
- تثبيت حزمة الأصول: فحص أن كل مسار `res://` مطلوب موجود فعليًا (سكربت التدقيق يفعلها).
- **مخرج**: `EchoNetwork-RC0-win64.zip` + بصمة + تقرير "يشتغل على جهاز لم يطوّر اللعبة".

**R3 — Android**
- تفعيل `gradle_build=true`، `internet=true` (خدمة الإيصال)، نسخ `versionCode/Name` صحيحة،
  استثناء `tests/`، توقيع keystore، إخراج **APK للتجربة + AAB للإصدار**.
- إعدادات رسومية مبدئية: Compatibility/Mobile قبل Forward+ على أجهزة ضعيفة (Vulkan OOM موثق).
- **مخرج**: APK يثبت ويعمل 20 دقيقة بلا انهيار + AAB موقّع.

**R4 — الأداء والقياس (فك G-09)**
- فئات جودة Auto/Manual (Low/Mid/High) مرتبطة فعليًا بالدقة والظلال والجسيمات والانعكاس.
- قياس: p50/p95/p99، GPU/CPU إن توفرت الأداة، RAM، زمن التحميل، حرارة الهاتف 20 دقيقة.
- أهداف: 30fps مستقرة على Infinix HOT 40 Pro (Low)، 60fps على PC مرجعي مسمى.
- LOD وتحميل مجاور وفصل أصول الغرف الثقيلة (المرآة أولًا).
- **مخرج**: جدول قياس موقّع بأسماء أجهزة وإعدادات، لا "PASS" بلا رقم.

**R5 — جاهزية Play**
- الأيقونة والصور والوصف AR/EN، تصنيف المحتوى، Data safety، الخصوصية، حذف الحساب،
  الأذونات الفعلية فقط، اختبار توزيع داخلي ثم إنتاجي.
- **مخرج**: AAB مقبول في مسار الاختبار + قائمة المتجر جاهزة.

### مسار C — الفن والحركة والمتعة

**C1 — مصنع الحركة (فك G-05)**
- إعادة استخدام Golden Walk كمفتاح مرجعي؛ إنشاء في Blender: Walk مؤهل، Wake/Getup،
  Interact (يد على محطة/باب)، Climb/Mantle، Dodge، Attack (خفيف/ثقيل)، Hit reaction، Land.
- لكل حركة: ملف مصدر `.blend` + glTF + `.res` + provenance (بصمة) + لقطات أمام/جانب/خلف.
- القبول: تماس قدم/يد، بلا انزلاق أو اختراق عباءة، يمر عبر `echo_v31_motion_adapter.gd`.
- **مخرج**: 8–10 حركات معتمدة داخل اللعبة.

**C2 — الوجه والقبضة والعباءة (فك G-06)**
- Blender: jaw + eye/brow bones أو shape keys، رمش، قبضة يد صحيحة، تحسين العباءة.
- تصدير glTF بـmorph targets، وفحص أن Godot يستوردها كـblend shapes.
- **مخرج**: مشهد حوار قريب مقبول (غرفة 01 أو 09) بلا تشوه رقبة/عين.

**C3 — كينجا وزيرو (فك G-07)**
- كينجا: قرار D-4 (بناء/هيكلة/تجميد) ثم rig بأصابع + وجه + 4–6 حركات تمثيل.
- زيرو: تأهيل يد العقد فقط، بلا إعادة تصميم هوية.
- **مخرج**: مشهد 09 + لحظة العقد مقبولان.

**C4 — الصوت والإتاحة (فك G-11/G-16/G-17)**
- مكتبة SFX: خطوات حسب السطح، هواء/مطر/معدن/بخار، تنفس، احتكاك، أبواب، نبض — **بلا موسيقى**.
- مزج مكاني، كتم، Reduced Motion، توقيت حوار AR/EN مع RTL.
- **مخرج**: استماع بشري + اختبار إتاحة + لا موسيقى في أي أصل.

**C5 — تمريرة الغرف 01→10 والفن النهائي**
- ترتيب واحد في كل مرة: فعل واضح → مهارة/قرار → كشف سردي → خروج مقروء → أداء مقيس.
- 09 و10 أولًا (الأقل إغلاقًا)، ثم إعادة صقل 01–08 بما لا يهدم المقبول.

### ترتيب التنفيذ المقترح (Critical Path)

```text
R0 → R1 → R2 (RC0 Windows) → R3 → R4 → R5
        ↘ C1 (متوازٍ من R0) → C2 → C3 → C4 → C5
```

RC0 يعتمد على: R0 + R1 + جزء من C1 (Walk مؤهل يكفي للعب) + جزء من C4 (حد أدنى SFX).
الفصل الكامل يعتمد على كل C + R4/R5.
