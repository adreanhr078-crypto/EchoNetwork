# عقد افتتاح الويب وغرفة Godot — الدفعة الرابعة

**الحالة:** انتقال مرشح غير مفعّل للاعب. الغرفة الحالية على الويب تبقى المسار القابل للعب إلى أن ينجح اختبار iframe الكامل على المتصفح والهاتف.

## تسلسل السلطة

1. يتحقق الويب من إيصال غلاف الافتتاح ومن `openingCoverPuzzleCompleted` لدى الخادم قبل كسر الشاشة.
2. بعد الكسر، يفحص المضيف حالة الخادم وحزمة Godot ووجود WebGL2. إذا لم تتوفر حزمة **معتمدة للعب**، ينتقل إلى غرفة الويب القائمة.
3. تصدير Godot ينشئ `manifest.json` مع `playable: false`. نجاح التصدير لا يجعل الغرفة متاحة للاعب. يتطلب تغيير هذه العلامة اختبار قبول متصفح وهاتف موثقاً.
4. عندما يصبح المشهد صالحاً، يرسل Godot أحداث العرض المسموح بها عبر `postMessage` نصي، بنفس الأصل، مع `bridgeVersion: 1` و`nonce` لكل جلسة. يتحقق المضيف من أصل الرسالة ومصدر الإطار والنسخة والـnonce. لا تمر بيانات الدخول أو إيصالات المكافآت عبر الجسر.
5. ترسل الغرفة أحداث القصة السبعة بالترتيب: `room_entered`, `clock_inspected`, `photo_inspected`, `memory_recovered`, `puzzle_solved`, `door_unlocked`, `memory_scene_completed`. يسمح بتبادل ترتيب المحطة والموصل داخل مهمة فتح البوابة، مع اشتراط إنجازهما معاً. يرسل المضيف طلب `/opening-room/complete` مرة واحدة بعد الحدث الأخير، ويتحقق من حالة الخادم والإيصال؛ عند ضياع الرد يقرأ حالة الخادم قبل أي محاولة أخرى.

## ما نُفذ وما لم يُقبل

- أضيفت ساعة وصورة قابلتان للتفاعل في غرفة Godot، مع حوار استرداد ذكرى قصير ومشهد ختامي عند الحد. فحص Godot الآلي يغطي المسار وترتيبي المحطة والموصل وإشارات التقدم. لا يثبت ذلك جودة اللعب اليدوية.
- أُعد مشهد Web افتتاحي محدود، ومُصدّر Godot Web بدون threads، ومضيف iframe مع مهلة تحميل وعودة إلى غرفة الويب. نجح تصدير Web محلياً، ونجح تبادل `ready/configured` في مشهد Godot خفيف.
- في Edge/Playwright وصل المشهد الكامل إلى `Main._ready`، لكن رسالة `ready` لم تُسلّم للصفحة الأم خلال 60 ثانية؛ تعطيل معالجة المشهد وإزالة نموذج اللاعب في تجربتي عزل لم يحلا المشكلة. لذلك **فشل قبول تشغيل الغرفة الكاملة داخل iframe**. لا توجد نتيجة أداء Android أو اختبار لاعب جديد.
- `playable: false` يجعل المسار الفعلي يعود إلى غرفة الويب. لا يُستخدم تصدير Godot الحالي لإتمام الغرفة أو منح مكافأة.

## قرار المتابعة

يعاد اختبار الشريحة في المحرك والعتاد المستهدفين، مع تأكيد ظهور الشخصية والتحكم والرسائل وإكمال المهمة، قبل تفعيل `playable`. قرار المالك اللاحق بدأ تقييماً لنقل الشريحة إلى Unity سحابياً؛ لا يغيّر ذلك سلطة الخادم أو حالة قبول Godot Web الحالية.
