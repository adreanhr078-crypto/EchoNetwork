# Echo Cinematic Room

Use a four-image visual contract to direct a Flow cinematic, select sharp frames, generate reusable Tripo resources, and assemble an editable playable room. Apply this to the room requested by the user; preserve its story, interactable landmarks, route and existing work.

## Establish the room contract

Read the project's current instructions, Canon, continuation and actual scene before designing. Record room dimensions, entrances, exits, objective, camera height, lighting palette and named landmarks. For EchoNetwork, begin at PROJECT_MAP.ar.md and artifacts/eleven-eleven/docs/internal/production/CURRENT_WORK.ar.md. Use the active Godot project and approved Manhwa; do not put later characters or powers in an earlier room.

Create a versioned production folder with a room manifest based on [assets/room-manifest.json](assets/room-manifest.json). Keep raw generated files, accepted derivatives and native evidence separately. Record source hashes and generation task IDs. This skill supplies a workflow, not new authorization to spend credits or publish.

## Four references before the cinematic

Produce exactly four separate images for the room: entry wide, reverse wide, lateral equipment view and hero landmark detail. Use the first accepted image and measured plan as continuity anchors for the remaining three. Preserve door positions, ceiling height, wall modules, prop identity, material palette and plausible scale across views. A detail image should not introduce a new floor plan.

Use the installed image-generation capability for new stills, or Flow's current image mode when requested and available. For edits, inspect local reference images first. Review every result for coherent geometry, readable materials and usable paths before submitting the four images with the cinematic prompt. Save actual image files in the project; a prompt or job ID is not an image.

Read [references/room-prompts.md](references/room-prompts.md) for the shared room description, four view prompts and Flow shot template. Adapt the language and performance to the project's approved audio direction.

## Direct and inspect Flow

Use the actual supported browser interface and the user's authorized Flow account. Check the currently available model, input-image limit, aspect ratio, duration and credit cost. Respect prior session authorization; ask again only for missing authorization or a material expansion such as buying a plan. Keep all four references in the submitted production packet. If the chosen mode accepts fewer individual images, use a supported storyboard/multi-shot setup or a reviewed four-view contact sheet while retaining the individual originals. Record the actual submission; do not silently drop a reference or claim four uploads from fewer inputs.

Describe a continuous camera move, stable architecture, intentional light changes and layered audio. Bind speech to approved dialogue; do not invent progression or consent. Record actual submission, status and charged credits. Preserve failed attempts as evidence. Do not regenerate identical failed requests blindly. When the site blocks generation, record the concrete blocker and continue approved independent asset work; leave cinematic acceptance open.

Download successful output through supported tools, inspect the entire take and listen to its audio before accepting. Check frame-to-frame geometry, unintended props or actors, blur, flicker and identity drift. Do not mark a scene accepted from its thumbnail. Retain the original video and select at least four sharp frames at recorded timestamps, including both wide spatial views and resource details. Frames inferred from prompts are not extracted evidence.

## Convert cinematic references into Tripo resources

A video supplies appearance and composition; hidden surfaces and physical dimensions need the measured room plan and explicit modeling decisions. Decompose the room into a coherent kit: structural modules, door frames, equipment, furniture and hero props. Preserve a bill of resources linking each object to a reference image or actual video frame.

Prepare clean object references with enough silhouette and surface detail for generation. If using Tripo multiview, all images must show the same static isolated object from genuinely different views; four different room shots are not four views of one object. Do not feed actors, moving VFX or baked shadows into a structural room mesh. Generate architectural modules and resources that can be rearranged and optimized in the engine; choose a whole-room mesh only when its interiors, openings, navigation and collision can actually be inspected and edited.

Use the installed Tripo game-asset workflow and current official API/CLI capabilities. Select quality parameters for the asset's viewing distance and performance budget, verify the cost, validate a dry-run when supported, then execute authorized jobs. Keep one shared spending ledger across workers. Use approved credential interfaces; do not put API keys in skill files, prompts, manifests or logs. Preserve successful task IDs and resume their downloads instead of paying for duplicates.

Inspect each source in Blender or the engine. Retain the raw model, create an editable derivative, set metres and measured pivots, separate unintended components, correct surface normals, and validate textures and triangles. Assess structural shape before adding emissive effects. Document hidden geometry decisions and any approximation; do not claim exact reconstruction from a cinematic.

## Assemble the playable room

Import the accepted kit into the existing engine. Reuse measured landmark transforms and maintain a continuous entrance-to-exit path. Replace visual geometry independently of existing triggers and authoritative interactions. Preserve the relevant colliders, readouts, lights and saved-state semantics; do not hide a broad parent containing them merely because it has a visual name.

Add animated environmental details and VFX with local elapsed time, stable material instances and bounded draw calls. Respect pause, Reduced Motion, mute and quality tiers. Add independent bone or cloth motion to characters only when their own rig is verified; never bake characters into environment resources.

Review the room from all four reference viewpoints and through actual player traversal. Check prop scale, hands and sockets where relevant, occlusion, camera collision, lighting, interaction readability, frame time, loading and memory. Numerical checks and headless tests do not establish artistic or device acceptance.

## Evidence and continuation

Use [scripts/validate_evidence.py](scripts/validate_evidence.py) to verify a packet's file paths, hashes and stage requirements. Its PASS concerns evidence integrity only. Record artistic review, native journey and performance separately in the manifest.

Delegate distinct useful tasks when supported: references and cinematic direction, asset generation, geometry cleanup, engine assembly and independent verification. Report workers that actually exist; coordinate shared files, budgets and GPU work. A larger worker count alone does not prove better quality.

Advance a room only after its required native checks and actual visual reviews pass. If a stage remains open, name it, preserve completed artifacts and record the next concrete action. Do not convert a storyboard, generation completion or asset count into a finished playable room.
